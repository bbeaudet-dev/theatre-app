Hi there, I'm looking to create an app centering around theatre and Broadway. It will have a few main functions. 

First, it will be a website that provides anyone with a calendar of all shows currently running on Broadway, off-broadway, etc., as well as any touring shows or local productions based on area. The calendar can be viewed just from the website, or it can also be added as a shared Google Calendar. This can simply be referred to as the "Calendar". 

Next, I want users to be able to stay up to date on any shows that they are interested in. At a higher level, this would include receiving updates about info regarding opening date, preview dates, closing dates, or if it's an open run, so that people can plan when they might want to see it, as well as new shows that are announced! At a more granular level, this could include info like cast changes (and dates), news headlines, reviews, etc. The most important aspects of this feature, which we can call "Notify", are to have a way of scanning the internet (or specfic sites or other sources) for news of new shows that are announced, show closings, etc. so that we can notify (text or email) users about these updates. The main benefit of this feature is so that people don't miss important new things or updates, and so that they don't have to regularly check for news and instead get all the info they need in a kind of notification. The "searching" feature will likely be accompoished with some usage of AI.

Third, I want to build a tool for users that helps them determine if they will like a show or not. One of my biggest "pain points" is figuring out if I will really enjoy a show or not when I'm deciding which ones to see, and doing so accurateyl without spoiling the show. This is a difficult task, because you truly never know until you try something. There are many shows that have pleasantly surprised me that I didn't think I would like going in, and there are shows that I had high expectations for but let me down. There are simply so many aspects of theatre to be "analyzed" that it's tough to ever give a definiteive answer. HOWEVER, I have gotten a lot of benefit from analyzing, especially when an AI has lots of context about what I already like/don't like (my show rankings), what elements of theatre I like the most, what themes resonate with me or not, etc., and so I think we can build something that has the power to give a pretty damn good answer about whether someone will like a show or not, especially with lots of previous context. I imagine that this feature will take the shape of somewhat of a chatbot, where the user starts by picking a show (or multiple), and the AI analyzes all the context it has, and then asks questions that will give it more info without spoiling any of the show, e.g. "Do you enjoy self-deprecating humor?"  If no, that would give a good indication that they might not enjoy a show like "Oh Mary!". Users could input a single show and ask if they would enjoy it, or they could input multiple shows and ask "Which one should I see?" Theoretically analzying multiple shows would just be the same "algorithm"/process as the single show, and then it would just compare the results at the end and give an answer for which one might be best. In addition to more individual-show-specific elements and questions, I think it would be great to have some more inputs on each user's profile, e.g. they could answer more general questions like "How much do you appreciate good dance in a show?", "Do you appreciate a live orchestra?", "Do you enjoy listening to soundtracks/songs from musicals in your daily life, and would you listen to songs again if you really enjoyed them?", etc. etc. basically some questions aroudn the more general areas of theatre. Off the top of my head, the things I evaluate shows on are: unique stage elements (e.g. Hadestown's moving stage, Sunset Boulevard's live camera, Wicked's Wizard head); "prop efficiency", or how much they can do with a little (e.g. Come From Away uses VERY minimal props, basically just a set of chairs, to tell the entire story, with the chairs representing the planes, the busses, the buildings in the town, the bar, etc., whereas something like Harry Potter had a lot of props but I felt it was an underwhelming use of them); how much i like the songs and if I would listen to them again, and if they are good "singalong" songs like in a piano bar; did I resonate with the message/lesson/moral of the story and do I walk away from the show having learned something or having a new perspective that I can apply to my daily life; dancing is a less significant element for me; quality of actors/performers; was I ever bored or confused; and maybe some others. Anyways, yeah that's the feature for helping someone decide how much they would enjoy a show / which one to see!

Fourth, I'd like to make some kind of "Plan" feature, which, unlike the Preview feature, which doesn't really have any time bounds and is just about deciding to see a show or not, the Plan feature would be more about actually planning out a trip. The main aspects of this are A) something similar to bwayrush.com, which collects all kinds of info, like which shows are currently on, which days and times they play, and where you can get tickets, including rush/lottery/other special deals. So essentially our tool would give a visual summary of all this so that someone could actively plan out a week/weekend in new york and see at a glance if a certain show is available at a certain time/date and how they could get tickets. I also imagine this feature working quite closely with the Notify feature, as I would want to notify users if a show that is on their "Interested in" list is going to be closing soon. And while I am designating these as separate features, it's very possible that the entire Plan/Preview/Calendar could be on a single page, e.g. we see a calendar view which also shows showtimes/dates, and there could be the chatbot on the side or corner so they could stay on the page. I'd say we probably aim for this first and then break them out later if needed. The Profile/Rankings feels like it should be a separate page, but I could always change my mind. 

Fifth, I want to give users a place where they can record and rank all of the shows they've seen! This is something my friends and I have always done and it just gives going to the theater another little fun twist. You can go to ../personal-portfolio/app/for-fun/theatre or visit the website at benbeaudet.com/for-fun/theatre to see my current implementation of a "theatre cloud", which essentially takes a user's list of ranked shows and creates a kind of "word cloud" out of them, making shows higher on the list appear bigger. Clicking on each playbill image brings up info about when/where/how many times they've seen the show, as well as any notes or reviews they have. I want to implement something very similar into this app, and have it closely connected to the other features too. For example, if a user has marked a show as "Interested in" and then they add that show to "Seen", then we could prompt them to remove it from the interested in list, or just automatically take it off. And their rankings factor heavily into the context that the AI would use to determine if that user would like a different show or not, or if they might be interested in a show that just got announced.

I need a responsive website, so probably React, and then I also need the capability to have a "subscription" list that I can send email/text/app notifications to, which would probably require some kind of database(?) so we can track which shows they want to stay up to date on? And then there will likely be some sort of AI integration so that we can scan for the info we need and then present it in a form that is useful to the user - this would apply to the Notify, Preview, and Plan features the most. 
In general, we need a good system for basically incorporating multimodal data, I think? Like we will have lots of context about each user, including the profile questions, their rankings of shows, their input on whether or not they liked shows that were recommended to them, etc. and I want to make sure we can clearly delineate different aspects/pages of the app, like a Profile page and a Calendar page and a Plan page, but also make them feel very integrated and holistic.
